# Web Admin 功能对照矩阵

本文对照 LDAPSoft LDAP Admin Tool Standard/Professional 的官方公开能力，规划
ldap-go Web Admin 的产品范围。对照基线为 2026-08-30；这里只比较公开描述的功能，
不推断 LDAPSoft 未公开的实现细节，也不复刻其界面、文案或专有查询语法。

## 官方来源

- [LDAP Admin Tool Standard Edition](https://www.ldapsoft.com/ldapbrowser/ldapadmintool.html)：多目录、用户与组管理、嵌套成员、搜索/可视化过滤、批量更新、复制移动、属性与图片编辑、密码编辑、导入导出和监控等公开能力。
- [LDAP Admin Tool Professional Edition](https://www.ldapsoft.com/ldapadmintoolprofessional.html)：在通用管理能力上增加预定义搜索、计划导出、命令行导出和计划 SQLDAP 等公开能力。
- [LDAPSoft 产品版本比较](https://www.ldapsoft.com/compare.html)：Standard、Professional 和 Reporting 等版本的公开能力边界。
- [LDAP Admin & Reporting Tool](https://www.ldapsoft.com/ldapreports.html)：预定义报告、嵌套组报告、计划报告及多格式输出等公开能力。

以上链接仅作为能力名称和范围的来源。本文全部说明均为摘要和独立设计，不复制受
版权保护的长文本。

## 分类定义

| 分类 | 含义 |
| --- | --- |
| 已有 | 当前 Web Admin 已有可调用的服务端能力和可用页面流程；仍受部署配置、服务器 Schema 与 ACL 限制。 |
| 本波实现 | 当前功能扩展迭代的交付范围。只有 API、页面、权限负例、资源边界和端到端测试全部完成后，才能转入“已有”。页面占位或仅有前端逻辑不算完成。 |
| 后续高价值 | 对生产管理有明确价值，但需要新的持久化模型、后台任务、跨服务器事务语义或更大测试矩阵，不应挤入本波。 |
| 不建议照搬或需独立安全设计 | 桌面工具语义不适合共享 Web 服务，或涉及专有语法、凭据托管、高风险写操作；不能按界面功能直接移植。 |

## 产品边界与安全原则

ldap-go Web Admin 是通过 LDAP 协议工作的独立 Web 客户端，不是绕过目录服务的
数据库控制台。登录建立真实 LDAP Bind，会话持有绑定后的 LDAP 连接；查询和写入
必须继续经过 LDAP 服务器的 ACL、Schema、Overlay、密码策略、审计和运行时限制。
页面是否显示按钮、客户端字段是否只读、前端是否隐藏某个条目，都不是授权依据。

Web 产品与桌面工具还有以下边界：

- Web 服务由多个浏览器会话共享，不能默认拥有桌面程序的本地文件系统、系统钥匙串、
  剪贴板、cron/Task Scheduler 或任意目标网络访问能力。
- 浏览器书签和历史可以只保存在当前浏览器；连接凭据、计划任务和共享报告不能放入
  `localStorage`，必须使用服务端加密、所有者隔离、审计和删除生命周期。
- 同一服务器内的 ModifyDN、跨命名上下文移动、跨服务器复制再删除具有不同原子性。
  页面必须明确展示操作类型和失败后的状态，不能统一伪装成“拖放成功”。
- LDAPSoft 是专有产品。ldap-go 只参考官方公开的能力分类，采用自己的信息架构、交互、
  API 和测试，不复制其 UI、图标、文案、布局、截图或内部行为。
- SQLLDAP 的完整语法和兼容语义并非 LDAP 标准。ldap-go 优先采用 RFC LDAP Filter、
  LDAP Controls 和 LDIF；如未来需要查询 DSL，必须独立定义、文档化并进行安全审计，
  不宣称兼容 LDAPSoft SQLLDAP。

## 已有

| 能力 | 当前 ldap-go Web Admin | 边界/说明 |
| --- | --- | --- |
| 连接与 Bind | 每个 `web-admin` 进程配置一个 LDAP URL；每个登录会话执行真实 Bind 并持有独立的有界连接。 | 这不是 LDAPSoft 所述的多连接配置库或同时打开多个目录。密码不在会话中保留。 |
| 目录浏览与用户管理 | 命名上下文树、分页列表、条目详情；Person、Group、OU 和自定义模板；Add、Modify、Delete。 | 模板只是录入辅助，最终合法性由目标服务器 Schema 和 ACL 决定。 |
| 用户组基础管理 | 可创建常见组条目，并通过通用属性编辑器维护 `member`、`uniqueMember` 或 `memberUid`。 | 尚不是专门的成员选择、反向成员关系或嵌套成员工作台。 |
| 高级搜索 | 支持 Base DN、base/one/sub scope、原生 RFC 4515 Filter、属性投影、大小限制和 Simple Paged Results 翻页。 | 已有的是精确 LDAP 搜索表单；当前不把 SQL 风格查询算作高级搜索。 |
| 重命名与移动 | 通过 ModifyDN 修改 RDN，并可指定 `newSuperior` 完成服务器允许的同连接移动。 | 服务器可能拒绝跨命名上下文移动；失败不应自动退化为复制后删除。 |
| 通用属性编辑 | 多值文本属性的 add/replace/delete；显示 Schema 提示；常见操作属性和二进制属性只读。 | 尚无按 Syntax 选择的 Boolean、Integer、Generalized Time、DN、Object Class、Hex/File 等专用编辑器。 |
| 二进制数据 | API 使用 Base64 表示二进制属性，页面可识别并只读显示。 | 当前没有安全上传、下载、图片预览、裁剪或格式转换。 |
| 密码修改 | 使用 Password Modify Extended Operation 重置密码，传输和访问受 Web/LDAP TLS、ACL 与密码策略约束。 | 页面不生成目录密码哈希；哈希算法由服务器策略决定。 |
| 导入/导出 | 有界 LDIF 导入与 LDIF 导出；导入仍逐项经过 LDAP 写操作、ACL 和 Schema。 | 当前 Web 页面不提供 CSV、XLSX、PDF、JSON 或 SQL 格式导入导出。 |
| Schema | 读取 Root DSE 的 subschema entry，展示 Attribute Types、Object Classes 及其他公开定义并支持页面筛选。 | 只读；不在通用管理页直接修改 `cn=config` 或 Schema。 |
| 监控 | 读取服务器公开的 Monitor naming context，展示有界的摘要和条目详情。 | 是实时只读快照，不是时间序列、告警或容量报告系统。服务器未公开或 ACL 不可见时不推断数据。 |
| 页面与运行安全 | 英文/简体中文切换、CSRF/Origin/Host 校验、HttpOnly 会话、请求与搜索资源限制、HTTPS/LDAP TLS 门禁、健康检查和聚合指标。 | 语言只影响界面文本，不转换 DN、属性名、OID、Filter、Schema、LDIF 或属性值。 |

## 本波实现（已落地）

本节能力已接入页面与真实 LDAP 请求，并有普通、race、权限负例和资源边界测试。
其中 Schema 专用控件当前对 Boolean 和单值 Integer 使用专用输入；DN、Generalized
Time 和未知 Syntax 暂时保留无损文本输入，避免浏览器格式化破坏原始 LDAP 值。

| 能力 | 本波范围 | 完成判定与安全要求 |
| --- | --- | --- |
| 用户组工作台 | 识别 `groupOfNames`、`groupOfUniqueNames`、`posixGroup` 等常见组；展示、添加和移除直接成员；支持 DN 与 UID 成员属性。 | 修改必须发送普通 LDAP Modify；不得通过前端缓存覆盖并发变化；成员不可见或写入失败时保留 LDAP 结果，不暗示管理员拥有额外权限。 |
| 嵌套成员 | 在组详情中按需展开直接和间接成员，标注来源层级，并提供循环检测。 | 必须限制深度、访问条目数、并发和耗时；只返回当前 Bind 身份经 ACL 可见的结果，不能用隐藏成员数量制造侧信道。 |
| 可视化过滤器 | 提供 AND/OR 条件组和常用等于、包含、前后缀、存在、范围、近似、否定操作；生成可查看、可继续编辑的 RFC 4515 Filter。 | 属性和值必须使用标准 Filter escaping；文本 Filter 始终是权威表示。首版不支持任意深度的拖放 AST，也不引入 SQL。 |
| 常用搜索与书签 | 内置人员、组、锁定账户等少量可审计模板；允许保存命名查询；记录有限的本地查询历史。 | 个人书签/历史首版仅保存在浏览器，不含 Bind 密码；提供清除入口、条数上限和失效字段处理。共享书签不在本波。 |
| 批量修改 | 对明确勾选的 DN 执行 add/replace/delete/increment；支持遇错停止或继续，返回逐条成功/失败/未知/未执行结果。 | 服务端限制 DN 数、属性数、值大小和整批耗时；操作前显示影响范围并二次确认。传输中断后的在途写结果标为未知并禁止直接重试。普通 LDAP 请求间不具备跨条目原子性，页面必须如实报告部分成功。 |
| 批量删除 | 对明确勾选的条目执行有界删除并展示逐条结果。 | 默认不递归；不把搜索结果全选隐式扩展到未加载页面；失败后不得从页面静默移除条目。 |
| 复制与克隆 | 同一连接内克隆单个条目到新 DN；复制用户可修改属性并确认后 Add。现有 ModifyDN 移动入口继续保留。 | 排除 `NO-USER-MODIFICATION` 等操作属性；目标 RDN 属性必须一致；不在本波做递归子树复制或跨服务器复制。 |
| Schema 感知属性编辑 | 根据公开 Schema 为 DN、Boolean、Integer、Generalized Time、Object Class 和普通文本选择合适控件；区分必需、可选、操作和不可修改属性。 | Schema 提示不能替代服务端校验；未知/自定义 Syntax 必须回退为不会破坏原值的通用编辑器。 |
| 二进制与图片 | 支持有界的二进制上传/下载；对 `jpegPhoto`、`thumbnailPhoto` 等明确图片属性提供安全预览和替换。 | 校验属性、字节数、解码结果、MIME、图片尺寸和像素总量；使用 Blob URL 并及时释放；SVG/HTML 不以内联活动内容渲染；原始字节未经确认不自动转码。 |
| 搜索结果导出 | 保留完整 LDIF；增加当前查询的 CSV 和 JSON 导出，明确多值、二进制/Base64、DN 和字符编码规则。 | 导出重新在服务端以当前 Bind 身份执行有界查询，不能信任浏览器提交的隐藏结果；CSV 防公式注入；JSON 不是 LDAP 迁移的规范格式。 |
| CSV 批量导入 | UTF-8/BOM/CRLF CSV、显式列映射、RDN 属性和对象类向导；先完整预检，再按行执行 Add 并报告逐行结果。 | 标准 `encoding/csv` 解析、DN 转义、行/属性/值/请求体限制；跨行不宣称原子，复杂迁移仍使用 LDIF。 |
| Schema/Monitor 易用性 | Schema 分类、名称/OID 搜索和定义详情；Monitor 刷新、关键计数分组及原始值查看。 | 仍保持只读、按需加载和资源上限；不把厂商特有 Monitor 属性解释成跨服务器通用指标。 |

## 后续高价值

| 能力 | 价值 | 前置设计/不放入本波的原因 |
| --- | --- | --- |
| 多连接与多目录 | 连接配置、标签页切换、同屏比较以及跨目录迁移是 LDAPSoft Standard/Professional 的核心公开能力之一。 | 需要连接配置所有权、LDAP URL 出站允许列表、DNS 重绑定防护、TLS CA/客户端证书生命周期、凭据加密、会话隔离、配额和审计。不能把密码或私钥放在浏览器存储。 |
| 跨服务器复制 | 支持在两个已授权连接间复制条目或子树，适合迁移和环境同步。 | 跨服务器不存在 LDAP 原子事务；需要 Schema 映射、DN 重写、引用属性策略、冲突预检、补偿/续跑和逐项审计。 |
| 递归子树复制/移动 | 降低 OU 或应用分支迁移成本。 | 必须处理排序、父子依赖、引用完整性、Overlay 副作用、部分失败恢复和规模上限；同服务器优先使用服务器支持的 ModifyDN。 |
| CSV 更新、幂等同步与高级字段映射 | 在本波 CSV Add 基础上支持 HR/业务系统的重复导入和更新。 | 仍需要幂等键、Add/Modify 策略、多值/二进制映射、预览差异和可恢复批次。XLSX 可在稳定 CSV 模型之上实现。 |
| XLSX/PDF 报告导出 | 方便审计、离线共享和管理层报告，对应 LDAPSoft Professional/Reporting 的公开方向。 | 属于报告呈现而非目录互操作；需要模板、分页、大结果流式生成、公式/链接安全、数据脱敏和下载保留策略。 |
| 团队书签和搜索历史 | 共享常用排障或审计查询，形成可复用操作手册。 | 需要服务端持久化、租户/角色 ACL、版本、审计、Filter 校验和敏感查询参数脱敏；不能直接同步浏览器历史。 |
| 预定义搜索和报告 | 提供人员、组、过期/锁定账户、修改时间等可配置模板，接近 Professional/Reporting 的生产效率。 | 必须按目标服务器能力和 Schema 探测启用，区分通用 LDAP、OpenLDAP 与 AD 语义，避免展示不准确的“通用”报告。 |
| 监控时间序列与告警 | 趋势、阈值、容量和失败率比单次 Monitor 快照更适合生产运维。 | 应接入 Prometheus/Alertmanager 等监控系统，Web Admin 只展示链接或受控摘要；不自建第二套长期指标数据库。 |
| 定时任务 | 计划执行导出、经过审批的批量变更或报告生成，对应 Professional 的计划能力。 | 需要独立 worker、任务队列、分布式互斥、重试/幂等、时区、审批、密钥托管、结果保留、通知和完整审计。 |
| 邮件/对象存储投递 | 自动分发计划报告或导出物。 | 需要收件人授权、传输加密、敏感数据分级、短期下载链接、保留/删除和泄露审计；不能由页面直接携带 SMTP/云密钥。 |

## 不建议照搬或需独立安全设计

| 能力/做法 | 决策 | 原因与替代方案 |
| --- | --- | --- |
| LDAPSoft UI、拖放和桌面工作流 | 不照搬。 | 专有 UI 受版权和产品识别保护，且桌面窗口、系统剪贴板、本地文件与拖放语义不适合共享 Web 服务。仅参考公开功能目标，按 ldap-go 的 Web 信息架构独立实现。 |
| SQLLDAP 语法兼容 | 不宣称、不直接实现兼容层。 | SQLLDAP 不是 LDAP 标准，公开页面不足以定义完整语法、空值、多值、DN、事务和错误语义。查询优先使用 RFC 4515 Filter，批量变更使用显式 LDAP 操作/LDIF；若需求成立，再设计 ldap-go 自有且默认只读的 DSL。 |
| SQL `INSERT/UPDATE/DELETE` 导入导出 | 不作为 LDAP 迁移格式。 | SQL 文本容易制造“数据库事务”错觉，并带来解析、注入和方言兼容风险。迁移采用 LDIF；表格交换采用有明确映射规则的 CSV/JSON。 |
| 浏览器生成并写入密码哈希 | 默认禁止，需独立专家模式评审。 | 客户端选 SHA/MD5/CRYPT 可能绕过密码策略、历史、国密策略和服务器 `olcPasswordHash`，还会鼓励弱算法。默认只调用 Password Modify，让服务器生成带盐哈希；原始哈希迁移使用受审计的 LDIF/离线工具。 |
| 在 Web 中保存 Bind 密码、私钥或连接密钥 | 禁止使用 Cookie 明文、`localStorage` 或普通数据库字段。 | 多连接/定时任务若必须托管凭据，应采用独立 secret store 或 envelope encryption、密钥轮换、最小权限、不可回显、所有者隔离和访问审计。 |
| 无界嵌套成员、全目录选择和递归复制 | 禁止。 | 循环组和大目录可造成资源耗尽；搜索结果还可能随时间变化。所有操作都要绑定明确 DN 快照，并限制数量、深度、时间、并发、响应字节和可取消性。 |
| 将批量 LDAP 操作描述为原子事务 | 禁止。 | 除非目标服务器明确支持并成功执行 LDAP Transaction，否则跨条目操作可能部分成功。结果必须逐 DN 展示并可导出失败清单。 |
| 通用页面直接编辑 ACL、`cn=config` 或 Schema | 需独立高安全管理面，不并入普通条目编辑。 | 这些变更可能立即扩大权限、破坏登录或使目录不可启动。未来若实现，需专用权限、预检、差异、审批、备份、回滚和锁定恢复流程。LDAP 服务器仍是最终授权者。 |
| Web 进程内置 cron 和报告邮件发送 | 不直接照搬桌面/Professional 调度方式。 | Web 副本扩缩容会导致重复任务，长期凭据也扩大攻击面。采用独立 worker 和外部调度/队列；页面只管理经过授权的任务定义。 |
| 伪造不可见成员、监控值或 Schema 推断 | 禁止。 | ACL 拒绝或服务器未公开的数据必须显示为不可用/未知，不能通过缓存、计数差异或客户端推断泄露目录信息。 |

## 建议交付顺序

1. 完成本波的服务端批量 API、组成员 API 和资源/ACL 负例，再接通页面；避免只有按钮没有可靠语义。
2. 完成可视化 Filter、个人书签/历史、单条目克隆和 Schema 感知编辑器。
3. 完成二进制/图片安全链路与 CSV/JSON 导出，并做真实 LDAP 端到端和大对象测试。
4. 本波验收后，再设计多连接与凭据模型；这是跨目录复制、共享任务和计划报告的共同前置条件。
5. 最后以独立 worker 建设定时任务和报告。SQL 风格能力只有在标准 LDAP Filter/LDIF 无法满足已验证需求时才立项。
